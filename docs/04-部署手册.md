# 部署手册 — AI Coding

> 本地一键上线（Docker Compose）+ 上云迁移指引 ｜ 更新：2026-09-15

## 1. 环境要求

| 组件 | 要求 |
| ---- | ---- |
| Docker Desktop | 4.x（含 Compose v2），内存分配 ≥ 6G |
| JDK 21 + Maven 3.9 + Node 20+ | 仅构建镜像产物时需要 |
| 端口占用 | 80 / 3000 / 3306 / 6379 / 8080 / 8848 / 9090 |

## 2. 一键上线（Docker Compose）

```bash
# 1) 构建产物（首次或代码变更后执行）
cd ai-coding-backend
mvn -q clean package -DskipTests -pl ai-coding-user-service,ai-coding-app-service,ai-coding-ai-service,ai-coding-gateway
cd ../ai-coding-frontend && npm install --registry=https://registry.npmmirror.com && npm run build

# 2) 配置环境变量（可选）
cp .env.example docker/.env   # 填入 DEEPSEEK_API_KEY 后把 AI_MOCK_ENABLED 改为 false

# 3) 启动全家桶（9 个容器）
cd ../docker && docker compose up -d --build
```

启动清单：MySQL（自动执行 `sql/create_table.sql` 建表）、Redis、Nacos、
user-service(8201)、app-service(8202)、ai-service(8203)、gateway(8080)、
frontend(80, Nginx)、Prometheus(9090)、Grafana(3000)。

## 3. 访问入口

| 入口 | 地址 |
| ---- | ---- |
| 平台主站 | http://localhost |
| API 网关 | http://localhost:8080/api |
| 部署站点分享 | http://{deployKey}.localhost（泛子域名） |
| Grafana 监控 | http://localhost:3000 （admin / admin123，预置「AI Coding 微服务监控」看板） |
| Prometheus | http://localhost:9090 |
| Nacos 控制台 | http://localhost:8848/nacos |

> `*.localhost` 无需改 hosts，浏览器/系统自动解析到 127.0.0.1。
> 上云后把 Nginx 配置里的 `localhost` 换成你的域名并加 DNS 泛解析即可。

## 4. 全链路自检（可直接粘贴执行）

```bash
curl -X POST http://localhost/api/user/register -H "Content-Type: application/json" \
  -d '{"userAccount":"demo1","userPassword":"password123","checkPassword":"password123"}'
TOKEN=$(curl -s -X POST http://localhost/api/user/login -H "Content-Type: application/json" \
  -d '{"userAccount":"demo1","userPassword":"password123"}' \
  | node -e "let d='';process.stdin.on('data',c=>d+=c).on('end',()=>console.log(JSON.parse(d).data.token))")
APPID=$(curl -s -X POST http://localhost/api/app/add -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" -d '{"initPrompt":"制作一个倒计时活动页"}' \
  | node -e "let d='';process.stdin.on('data',c=>d+=c).on('end',()=>console.log(JSON.parse(d).data))")
curl -N "http://localhost/api/chat/stream?appId=$APPID&message=%E5%BC%80%E5%A7%8B%E7%94%9F%E6%88%90&token=$TOKEN"
# 看到 done 事件后：
DKEY=$(curl -s -X POST "http://localhost/api/app/$APPID/deploy?token=$TOKEN" \
  | node -e "let d='';process.stdin.on('data',c=>d+=c).on('end',()=>console.log(JSON.parse(d).data.deployKey))")
curl -I "http://$DKEY.localhost/"
```

## 5. 架构与数据流

```
浏览器 ── 80(Nginx: 前端静态 + /api 反代 + 泛子域名站点托管) ── 8080(Gateway: JWT 鉴权/路由)
   ├─ user-service(8201)  注册/登录
   ├─ app-service(8202)   应用/版本/部署/广场/预览   ── Dubbo Provider
   └─ ai-service(8203)    LangChain4j/LangGraph4j 生成工作流 ── Dubbo Consumer
共享卷：workspace-data（生成产物，ai 写 / app 读）、deploy-data（部署产物 → Nginx 托管）
Nacos(8848)：Spring Cloud 服务注册 + Dubbo 注册中心（接口级注册）
```

## 6. 上云迁移（单台 4C8G 即可）

1. 服务器安装 Docker + Compose，把项目推上去后执行 `docker compose up -d --build`。
2. 域名 DNS 加泛解析 `*.yourdomain.com → 服务器IP`；修改 `ai-coding-frontend/nginx.conf`
   两处 `localhost` 为 `yourdomain.com`；HTTPS 建议用 Certbot/Let's Encrypt 加 443 监听。
3. 生产配置：修改 `jwt.secret`、MySQL 密码、关闭 `AI_MOCK_ENABLED`、开启 MySQL 数据卷备份。
4. 安全项：网关仅暴露 80/443；数据库/中间件不暴露公网端口；建议增加 Sentinel/SLB 按需扩展。

## 7. 常见问题

| 现象 | 处理 |
| ---- | ---- |
| 启动报 `Cannot load driver class: com.mysql.cj.jdbc.Driver` | 重新 `mvn clean package`（增量打包可能产生陈旧 jar） |
| Dubbo 报 `No provider available` | 确认 provider `@EnableDubbo` + 双方 `register-mode: interface`（消费侧 FORCE_INTERFACE） |
| 分享链接 404 | deployKey 已统一小写；旧数据重新点一次「部署」 |
| SSE 无事件 | Nginx `proxy_buffering off` 已内置；检查网关路由与超时 |
| 想用真实大模型 | `docker/.env` 填 `DEEPSEEK_API_KEY`、`AI_MOCK_ENABLED=false`，重启 ai-service |

## 8. 本地开发（不走 Docker）

- 单体模式：`ai-coding-backend/ai-coding-single` 直接 `mvn spring-boot:run`（8123，context=/api），前端 dev 代理已指向 8123。
- 微服务模式：`mvn install` 后分别 `spring-boot:run -pl` 四个模块（需本机 MySQL/Redis/Nacos），前端代理改指 8080 即可。
