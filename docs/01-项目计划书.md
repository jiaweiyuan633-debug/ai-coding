## 1. 项目概述

### 1.1 一句话定位

**「AI Coding」是一个对话式零代码应用生成平台**：用户用自然语言描述需求，AI 自动生成完整可运行的网页应用，支持实时预览、对话修改、可视化编辑、版本回滚，并一键部署分享。

### 1.2 项目背景

AI 代码生成是当前最热的产品方向之一。以 v0.dev、bolt.new、lovable.dev 为代表的「AI 应用生成器」在海外增长迅猛；国内市场仍处于早期，存在明显的本土化机会。本项目以此方向为实战载体，完整覆盖 **AI 应用开发（LangChain4j / LangGraph4j / 工具调用 / 工作流）+ 微服务架构（Spring Cloud Alibaba + Dubbo）+ 企业级工程化（多级缓存 / 监控 / 多租户 / 设计模式）**。

### 1.3 目标用户

- 想快速做出可分享网页的非程序员（活动页、作品集、小工具）
- 需要快速原型的产品经理 / 设计师 / 创业者
- 学习 AI 应用开发与微服务架构的开发者（本项目本身即全栈实战样板）

### 1.4 成功标准（北极星指标）

新用户从「输入第一句需求」到「拿到可访问的分享链接」全流程 ≤ 5 分钟，且全程无需写一行代码。

## 3. 差异化创新点

1. **透明工作流（Transparency-first）**：LangGraph4j 编排「智能路由 → 代码生成 → 质量门禁（HTML/JS 静态校验）→ AI 自动修复（≤3 轮）→ 截图封面」，每个节点的开始/结束/产物通过 SSE 实时推送到前端时间线，生成过程全程可见——市面产品多为「黑盒转圈」。
2. **版本时光机**：每次对话修改自动生成版本快照（版本树，含父版本关系），支持一键回滚、任意版本对比预览。
3. **多模型路由**：策略模式抽象 AI 客户端，支持多家 OpenAI 兼容模型（DeepSeek 默认），按任务复杂度与用户选择路由，模型可热切换。
4. **用量中心**：所有模型调用全量计量（token 输入/输出、耗时、次数、成功失败），按应用/用户/天多维度聚合，支撑多租户配额与成本治理。
5. **模板广场 + Remix**：精选应用广场与模板市场，任何公开应用可一键「Remix」复制为自己的新应用二次创作。

## 5. 总体架构

### 5.1 单体期（阶段 2–4）

```
Vue 3 前端 ──HTTP/SSE──> Spring Boot 单体（ai-coding-backend）
                            ├─ user 包：注册/登录(JWT)/用户管理
                            ├─ app 包：应用 CRUD / 版本时光机 / 广场
                            ├─ ai 包：LangChain4j 客户端(多模型) + LangGraph4j 工作流 + SSE 推送
                            └─ deploy 包：静态托管 + deployKey 分享
存储：MySQL 8（业务数据）｜ Redis（会话/缓存）｜ 本地静态目录（生成产物+部署站点）
```

### 5.2 微服务期（阶段 6）

```
Vue 3 → Gateway(8080) → user-service / app-service / ai-service / deploy-service / screenshot-service
                          └─ Dubbo 3 RPC 互联，Nacos 注册+配置，Sentinel 限流熔断
热点读：Redis + Caffeine 多级缓存（应用广场、模板、用户信息）
监控：各服务 Micrometer → Prometheus → Grafana 看板
```

### 5.3 核心工作流（LangGraph4j）

```
[入口] → 智能路由(选择生成类型/模型) → 代码生成(工具调用写文件, SSE 流式)
      → 质量门禁(HTML/JS 静态校验) --失败--> 自动修复(≤3 轮) --成功/超限--> 完成(快照+封面+入库)
每个节点状态(开始/结束/错误/产物摘要) → SSE → 前端时间线实时展示
```

## 8. 部署方案

- **本地（当前目标）**：Docker Compose 编排 MySQL、Redis、后端、Nginx（前端静态资源 + 生成站点静态托管）、Prometheus、Grafana；生成站点通过 `http://<deployKey>.localhost` 泛子域名访问（浏览器天然支持，无需改 hosts）。
- **上云路径（预留）**：单台 4C8G 云服务器 + 一个泛解析域名 `*.yourdomain.com` 即可平移；Nginx 泛子域名规则与 Compose 编排完全复用。详见 [04-部署手册](./04-部署手册.md)（阶段 7 产出）。

## 9. 风险与应对

| 风险 | 应对 |
| ---- | ---- |
| DeepSeek API Key 未就绪/网络不稳 | AI 客户端抽象 + Mock Provider，开发联调不阻塞；Key 通过 .env 注入不入库 |
| AI 生成结果质量不稳定 | 质量门禁 + 自动修复工作流；组件化提示词约束输出格式 |
| 微服务组件多、调试复杂 | 先单体后拆分；每阶段可运行可回退 |
| 本机资源有限（多容器） | Compose 内存限制 + 按需启停；微服务期压缩并行度 |
| 流式输出在代理/超时下中断 | SSE 心跳 + 断线重连 + 任务幂等恢复 |

## 10. 合规与安全

- 密钥/环境变量一律 `.env` 本地注入，永不入库（.gitignore 已覆盖）
- 登录态 JWT + 接口鉴权；管理端角色隔离
- 多租户数据隔离（appId/userId 全链路校验）；AI 输出仅托管静态资源，不提供任意服务端执行
- Prompt 注入防护：系统提示词与用户输入分层，输出不回注系统指令
